# SidePulse — техническое задание

## 1. Суть проекта

Небольшая утилита для Windows, которая показывает в **мини-окне на краю экрана**
(панель сбоку, всегда поверх других окон) в реальном времени:

1. **Загрузку оперативной памяти** — занято в % и в ГБ.
2. **Температуру процессора** (CPU).
3. **Температуру видеокарты** (GPU).

Главная цель — чтобы состояние ПК было видно одним взглядом, без открытия
диспетчера задач и сторонних оверлеев.

Рабочее название — **SidePulse** (можно переименовать).

## 2. Обязательный функционал (MVP)

| # | Требование | Детали |
|---|---|---|
| F1 | Окно-оверлей | Без рамки заголовка, всегда поверх окон (topmost), перетаскивается мышью, вертикальная панель у правого края. |
| F2 | ОЗУ | Занято, % и в ГБ; обновление раз в 1 сек. |
| F3 | Температура CPU | Градусы, обновление раз в 1–2 сек. |
| F4 | Температура GPU | Градусы, обновление раз в 1–2 сек. |
| F5 | Иконка в трее | Свернуть/показать панель, выход. |
| F6 | Настройки | Хранить позицию панели, набор метрик, интервал, прозрачность, тему. |
| F7 | Цветовые пороги | Зелёный/жёлтый/красный по порогам (напр. <60 / 60–80 / >80 °C; ОЗУ <70 / 70–90 / >90 %). |

## 3. Желательный функционал (после MVP)

- Загрузка CPU и GPU в %.
- Частота CPU/GPU, обороты вентиляторов.
- Графики/история за последнюю минуту.
- Автозапуск с Windows.
- Несколько тем оформления.
- Оповещение при перегреве.

## 4. Источники данных (Windows) — важно

| Метрика | Рекомендуемый источник | Фолбэк |
|---|---|---|
| ОЗУ | `psutil.virtual_memory().percent` / `.used` | — |
| CPU temp | **LibreHardwareMonitorLib.dll** через `pythonnet` (секция CPU → Temperature) | WMI `root\LibreHardwareMonitor` (если запущено приложение LHM); при отсутствии — показать `n/a` |
| GPU temp | LibreHardwareMonitorLib (секция GPU) | `pynvml` (`nvmlDeviceGetTemperature`) для NVIDIA |

**Ключевой факт:** на Windows `psutil.sensors_temperatures()` температур **не
отдаёт** — нужен LibreHardwareMonitor (или другой низкоуровневый провайдер).
Именно поэтому в стеке pythonnet + LibreHardwareMonitorLib.

Приоритет источников сделать настраиваемым и с автоматическим фолбэком:
если датчик недоступен — показывать `n/a`, а не падать.

## 5. Технологии

- **Язык:** Python 3.10+ (проверено на 3.12).
- **UI:** Tkinter (стандартный, без тяжёлых зависимостей). Допустимо PySide6, если нужен более красивый UI — но обосновать.
- **Сбор метрик:** `psutil`.
- **Температуры:** `pythonnet` + `LibreHardwareMonitorLib.dll`, фолбэк `pynvml`.
- **Трей:** `pystray` (или `infi.systray`).
- **Сборка .exe:** PyInstaller (onefile) + установщик Inno Setup 6.

## 6. Архитектура (предлагаемая)

```
SidePulse/
├─ src/
│  ├─ main.py              # точка входа
│  ├─ core/
│  │  ├─ metrics.py        # сбор: RAM, CPU temp, GPU temp (единый интерфейс)
│  │  ├─ sources/          # провайдеры датчиков
│  │  │  ├─ ram.py         # psutil
│  │  │  ├─ cpu_temp.py    # LHM / WMI
│  │  │  └─ gpu_temp.py    # LHM / pynvml
│  │  └─ config.py         # настройки (JSON в %APPDATA%\SidePulse\config.json)
│  ├─ ui/
│  │  ├─ panel.py          # окно-оверлей, отрисовка, цвета/пороги
│  │  └─ tray.py           # иконка в трее
│  └─ lib/                 # LibreHardwareMonitorLib.dll (если поставляем)
├─ tests/                  # pytest: метрики (моки), конфиг, пороги
├─ packaging/
│  ├─ build.ps1            # PyInstaller
│  └─ installer.iss        # Inno Setup
├─ run.bat
├─ pyproject.toml
└─ README.md
```

**Контракт модуля метрик** (единый интерфейс, чтобы UI не знал про источники):

```python
@dataclass
class Sample:
    ram_percent: float
    ram_used_gb: float
    cpu_temp_c: float | None  # None -> показать "n/a"
    gpu_temp_c: float | None


class MetricsCollector:
    def read(self) -> Sample: ...
```

UI опрашивает `read()` по таймеру (по умолчанию 1000 мс), источники выбираются
при старте один раз с фолбэками.

## 7. UI/UX

- Узкая вертикальная панель (ширина ~140–180 px), прижата к правому краю,
  полупрозрачный тёмный фон, крупные цифры.
- Строки: `ОЗУ 62%  10.1 ГБ`, `CPU 54°C`, `GPU 47°C` — крупно, читаемо.
- Цвет цифры по порогам (F7).
- Правая кнопка мыши / трей → меню: «Настройки», «Скрыть», «Выход».
- Клик по панели не мешает работе; окно `-topmost`, `overrideredirect`.
- Запоминать позицию и размер между запусками.

## 8. Настройки (`%APPDATA%\SidePulse\config.json`)

```json
{
  "position": {"x": 1800, "y": 200},
  "metrics": ["ram", "cpu_temp", "gpu_temp"],
  "interval_ms": 1000,
  "opacity": 0.85,
  "theme": "dark",
  "thresholds": {"cpu": [60, 80], "gpu": [60, 80], "ram": [70, 90]},
  "autostart": false
}
```

## 9. Платформа и ограничения

- ОС: **Windows 10/11** (x64).
- Некоторые датчики (особенно CPU temp) требуют **прав администратора** —
  предусмотреть поведение без прав (`n/a` + подсказка), а не краш.
- GPU temp для NVIDIA — через NVML (драйвер NVIDIA). Для AMD/Intel — через LHM.
- Приложение не должно грузить систему: опрос раз в 1 сек, без тяжёлых циклов.

## 10. Критерии приёмки (Definition of Done)

1. Панель появляется на краю экрана, поверх окон, перетаскивается, не мешает работе.
2. ОЗУ, температура CPU и GPU обновляются в реальном времени (раз в ~1 сек).
3. Если датчик недоступен — показывается `n/a`, приложение продолжает работать.
4. Иконка в трее: показать/скрыть/выход; корректное завершение процесса.
5. Настройки сохраняются и восстанавливаются между запусками.
6. Есть тесты (`pytest`) на пороги/конфиг/метрики с моками; проходит `ruff check`.
7. Собирается `.exe` и установщик; установка идёт отдельно в свою папку.
8. README с инструкцией запуска и сборки.

## 11. Этапы (milestones)

1. Скелет проекта, `pyproject.toml`, `run.bat`, конфиг.
2. Модуль метрик: RAM + CPU temp + GPU temp с фолбэками (тестируется без UI).
3. Окно-оверлей: отрисовка трёх метрик, пороги, обновление.
4. Трей, настройки, сохранение позиции.
5. Тесты + линт.
6. Сборка `.exe` + установщик.
